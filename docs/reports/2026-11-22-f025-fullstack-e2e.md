# F025 全链路 E2E — Hub 多 agent / 同 thread / multi-mention / 跨 thread

## 1. 结论

operator 要求的完整前后端 E2E 已用真实 provider 跑通：Hub 创建 3 个 agent，
thread 1 完成 operator → A → B → A → operator，A 对 B+C 发起 multi-mention

双向跨帖；Hub 显示 sender displayName、multi-mention 汇总标记、跨帖来源 badge
与跳转。

## 7. 本次 E2E 暴露并修复的问题

### P1 — v1 A2A tool schema 缺少 JSON Schema `type`（已修）

首次真实 provider 调用直接 400：

```text
tools.function.parameters is not a valid moonshot flavored json schema,
details: <At path 'properties.triggerType': type is not defined>
```

根因：`multi_mention.triggerType` 只有 `enum`，嵌套 `target.kind` 只有 `const`，
都没有 `type`。Kimi/Moonshot 的 function schema 校验要求显式 type。

修复：`tool-surface.ts` 给 `triggerType` 加 `type:"string"`、给 `kind` 加
`type:"string"`；新增 `f025-tool-schema.test.ts` 递归断言所有 tool property
（含 array items）都有 `type`。修复后同一 invocation retry 成功。

### P3 — multi-mention 后 A 被多次唤醒（未修，记录）

B/C 的 `@agentA` 回帖和 multi-mention aggregate 各自唤醒 A，A 额外产生两条
「当前没有新消息 / 仍无新消息」响应（thread 1 seq 17–18）。不丢消息、不阻塞
测试，但属于可收敛的噪音：后续可做 callback 唤醒合并或 agent 侧抑制。

### P3 — Hub sender / provenance（已修）

原 MessageList 用 raw agentId 作 sender，且不显示 `extra.crossPost`；本次已改为
displayName + 跨帖 badge/跳转，并给 multi-mention aggregate 加标记。

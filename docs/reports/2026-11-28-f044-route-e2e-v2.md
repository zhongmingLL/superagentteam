## 逐项证据

### R1 并行 skew + 独立结算

- 场景：`@a1 @b1`，A 的 mock 延迟 900ms，B 立即返回。
- 断言：B reply 出现时，B attempt `handled`/turn `completed`/R `completed`/draft
  deleted；A attempt 仍 `appended`/turn `running`/R `processing`；随后 A 完成，
  parent `completed`，queue 空；B 的 prompt 不含 `A_SLOW_REPLY`。
- 意义：同时验证 route barrier（context 先装配）与 per-target 独立 T1/T2/T3，
  旧 inline fan-out 无法区分这两件事。

### R2 delivered provider failure + 手动 retry

- 场景：mock A 第一次返回 HTTP 500，第二次成功。
- 结果：attempt 1 `failed`，terminalReason `provider_error: 500 ...`，settlement
  `settled`；parent 先 failed（T3 完成），queue 空；UI/API retry 后 attempt 2
  `handled`，R 内容 `A_RETRY_OK`，parent completed；无 `delivery_failure`。
- 语义：prompt 已被 worker 接收，provider 500 属于 0010 §6.1.3 row 7 的
  **delivered failure**（T1 failed + ack），不是 pre-accept 的自动 backoff。
  pre-accept backoff 已由 `f044b-phase-b-ownership.test.ts` 的回归用例覆盖。

### R3 运行中取消

- 场景：mock 延迟 5s；API cancel 与真实 UI 停止各跑一次。
- 结果：attempt `canceled`/`operator_canceled`，turn `canceled`，R `canceled`，
  parent `canceled`，queue 空，worker `retired`。
- UI：LivePill 消失，消息显示“已取消”；截图见下。

### R4 cross_post 跨 thread

- 场景：thread1 的 A 调 `superagentteam_cross_post_message` → thread2 的 B。
- 结果：thread2 收到 agent input `CROSS_FROM_T1`，dispatchRef 指向 b1；
  thread1 的 A 与 thread2 的 B 两个 parent 均 `completed`；route 日志 events
  `phase_b_appended`/`turn_worker_bound`/`turn_terminal` 各 ≥2。

### U 层真实 Hub

- **U1 真实单 agent 成功**：`@agentA 请只回复：REAL_UI_OK` → 真实 Kimi 返回
  `REAL_UI_OK`（含 thinking）；DB attempt handled/settled、turn/R completed。
- **U2 真实多 target 成功**：`@agentA @agentB 请各自只回复：REAL_MULTI_OK` →
  Agent A/B 各返回 `REAL_MULTI_OK`，thread 显示 2 位成员；两个 parent completed。
  另有一轮 mock 多 target 作为确定性补充（`MOCK_UI_A_OK`/`MOCK_UI_B_OK`）。
- **U3 停止**：`SLOW_UI` 触发 mock 延迟 8s；点击“停止 Agent A1”后 UI 显示“已取消”；
  DB attempt/turn/parent 均 canceled，worker retired。

## 追加：R7 Phase B fault injection（2026-11-28）

在 `f044-route-fullstack-e2e.test.ts` 用真实 daemon + 真实 pi worker + mock provider，
对 Phase B 的三个事务步骤各注入一次 throw：

| 注入点 | delivery_failure reason | 断言 |
|---|---|---|
| `drafts.create` | `draft_create_failed` | attempt failed / `phase_b_failed`；无 TurnExecution/R；parent 仍 running；target 仍在 queued；provider 0 调用 |
| `credentials.create` | `credential_mint_failed` | 同上 |
| `queue.retireTargets` | `retire_targets_failed` | 同上 |

三例均证明 Phase B 失败不会进入 provider convergence，也不会丢 target：整个 Phase B
事务回滚，`delivery_failure` 精确记录失败步骤，queue entry 保留 target 等 bounded retry。
fullstack 文件 7/7；daemon 全量 543/1 不变。

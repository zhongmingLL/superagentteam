# F053 Queue steer — implementation report

## 背景

Clowder F047 Queue Steer 允许 operator 对排队消息逐成员选择「接进当前回复」或
「停下并处理这条」。SAT 只有只读 QueueStrip；本次把 pi worker 已原生支持的
`steer` RPC 接到 daemon 的 queue + tracker + WorkerPool 链路，并提供 Hub 操作面。

## Clowder 参考

- `docs/features/F047-queue-steer.md`：queued 行 Steer；guide 不自动 cancel；
  interrupt 先 cancel 再以同一 Queue row 启动；`processing` 不提供 Steer。
- `packages/web/src/components/SteerQueuedEntryModal.tsx`：目标选择 + 逐目标
  strategy；`guide_reply` / `interrupt_reply`。
- 本次 v1 采用逐 target 顺序提交（非 Clowder 的 atomic multi-target reconcile），
  sibling 独立终局；这是明确的范围收窄，不是隐藏差异。

## 实现

### 后端

- `SteerRegistry`：`(threadId, agentId)` → `{ turnExecutionId, attempt, steer }`；
  仅覆盖 `RunAgentTurn` 的 prompt 窗口，daemon 重启后为空。
- `RpcConnection.steer(message)`：发送 pi worker `steer` RPC，返回
  `handled | queued` disposition；`WorkerRpcConnection.steer` 可选。
- `SteerService`：
  - thread owner / entry `queued` / target pending 校验；
  - target-scoped short claim（15s）；
  - guide：tracker exact `turnExecutionId` fence → `steer(content)` → input
    `dispatchRefs`（dispatched）→ retire target；不 cancel；
  - interrupt：`tracker.cancel`（若有）→ `priority=urgent` →
    `QueueProcessor.processEntry`；sibling 保持 pending；
  - 失败路径 release claim，并返回 typed code。
- `POST /api/threads/:threadId/queue/:entryId/steer`：
  `{ targetAgentId, mode }`；CSRF、thread owner、400/404/403/409/422/502 typed；
  成功后 publish `queue` + `live`。

### 前端

- `QueueStrip`：仅 `queued` 行显示「处理这条」；`claimed` 行不显示。
- `SteerQueueDialog`：目标复选 + 每个目标独立的 guide/interrupt；guide 在无活动
  轮次时禁用；多目标按顺序提交，失败在弹窗内显示。
- `a2aApi.steerQueue` + `useA2AStore.steerQueue`：成功后刷新 queue/live。

## 已知限制

- guide 仅在 worker prompt 窗口内可用；完成/重启后返回 `no_active_turn`。
- pi steer 只在当前 assistant turn 的工具调用结束后、下一次 provider 请求前注入，
  不是硬中断 provider 调用。硬中断走 interrupt。
- 多目标顺序提交非原子；某目标失败不回滚已成功的 sibling（Clowder per-target
  独立终局同义）。
- interrupt 若旧 worker 仍占用，`processEntry` 会 release claim 并以 urgent 重试；
  不 double-start。
- 未实现 reorder / promote / supplement / append-to-existing-run。
